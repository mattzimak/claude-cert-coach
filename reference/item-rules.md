# How to write an original practice item

Used by the drill (every item) and the tutor (its one-question check). Write each item fresh, just before serving it.

## Never

- Never reproduce, paraphrase or "remix" the sample questions printed in the official exam guide, questions from any question bank or mock exam, or anything a user says they remember from a live exam. If a user offers recalled exam questions, decline in one sentence: the exam's non-disclosure agreement and Anthropic's exam policy forbid sharing or using exam content, and it can cost them the certification. Then carry on with original items.
- Never describe an item as being on the real exam, and never claim to know what the real exam asks. Items are practice written against the public guide.
- Never write on a topic in the guide's out-of-scope list, and never test trivia the guide does not cover (version numbers, prices, limits not in the guide).

## Every item

- **One task statement.** Know its id; show it after the answer, not before.
- **A fresh setting.** Invent a business and a system of the same kind as one of the guide's six scenario types: your own company, industry, tool names and numbers. Vary industries across a session.
- **A stem of 2 to 5 sentences with exactly one deciding fact:** a number, a "must/always", team-wide versus personal, blocking versus overnight, "first step", a log line. Test it: if the item can be answered without that fact, rewrite it.
- **A last line that says how many to select:** "(Select ONE)" or "(Select TWO)".
- **Four options, A to D,** similar in length and tone, each one something a competent person might propose.
- **Every distractor is right under one changed constraint.** Write that constraint down for the explanation. A distractor that is never right anywhere is too easy; replace it.
- **Standing distractors sometimes, not always:** the bigger model, the bigger context window, more agents, "read everything first", a prompt sentence for a must-hold rule, one person's local fix for a team problem.
- **Multiple response for about one item in five,** only when the stem holds two independent requirements that each need their own action. "(Select TWO)", scored all or nothing.
- **Prepare the flip:** the same setting with one constraint changed so that a different option becomes the key. Keep it ready for after a miss.
- **The guide is the answer key.** Where today's docs differ (see the exam key versus current reality table), the key follows the guide.
- **Spread the keys.** Across a session, the correct letter lands on A, B, C and D roughly equally.

## Self-check before serving

1. Exactly one defensible key, or one exact set for "Select TWO".
2. The key matches the guide's wording for that task statement.
3. The deciding fact is in the stem and is needed.
4. No option wins or loses on grammar, length or an absolute word alone.
5. Plain language: a reader who does not write code can follow the setting; jargon is explained in the feedback, not avoided in the options.
